# Data

Source: [KKBox churn prediction competition](https://www.kaggle.com/competitions/kkbox-churn-prediction-challenge/data).
Each contributor must obtain access and accept the competition terms using their
own account. Download the original files into `data/raw/`.

## Folder map

| Location | Contents | How it is used |
| --- | --- | --- |
| `raw/*.csv.7z` | Seven original competition archives | Preserve these as the source downloads |
| `raw/WSDMChurnLabeller.scala` | Provider's label-generation reference | Read to understand the label rules |
| `raw/metadata/` | Local download manifest, checksums and earlier inventory records | Source provenance; these are audit records, not current analysis results |
| `processed/eda/` | Current aggregate tables, charts, `summary.json` and generated `01_eda.executed.ipynb` | Inspect the latest local EDA results |
| `processed/eda/cache/` | Extracted label, profile, transaction and updated-log CSVs | Reuse decompressed files; subfolders mirror archive member paths |
| `processed/eda/cohort_cache/` | Sampled pre-cutoff listening records and their manifest | Reuse all retained history without rescanning the original archive |
| `processed/kaggle-eda/` | Output-cleared notebook snapshot and Kaggle metadata | Generated by `scripts/prepare_kaggle_eda.py` for private upload |

`notebooks/01_eda.ipynb` is the maintained source. The executed notebook under
`processed/eda/` is a generated results copy. Its cell outputs can contain source
previews and must stay local/private.

The current analysis keeps versions separate and uses a fixed customer sample
across related histories. Record source versions, sizes, checksums, date ranges,
sampling seed and prediction cutoff whenever the study design changes.

## What can be regenerated?

Files under `processed/` are generated. The notebook recreates extracted CSVs from
the original archives when needed. Rebuilding the original-listening sample cache
requires a full source scan, so keep the matching all-history cache for faster
reruns. The original 30 GB listening CSV is streamed rather than extracted to disk.

Keep downloaded data, customer records, credentials and generated outputs out of
Git. Only the folder placeholders are tracked inside `raw/` and `processed/`.
Public demonstrations must use synthetic or otherwise permitted data.
